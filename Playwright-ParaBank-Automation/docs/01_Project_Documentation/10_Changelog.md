# Versioning Strategy

The project follows Semantic Versioning (SemVer):

```text
MAJOR.MINOR.PATCH
```

Example:

```text
1.0.0
```

Where:

- **MAJOR** – Breaking changes or significant architectural updates
- **MINOR** – New features or completed automation modules
- **PATCH** – Bug fixes, documentation updates, and minor improvements

# Maintenance Guidelines

Update the changelog whenever:

- A new feature is implemented
- A new automation module is completed
- Framework architecture changes
- Documentation is updated
- CI/CD pipeline changes
- Major bug fixes are introduced

The newest release should always appear at the top of the release history.
